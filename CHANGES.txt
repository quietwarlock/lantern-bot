Lantern 1.11.1
==============

Fixed
- Web page, Discord page: the Queue card could cover the bot status and
  Now playing cards (and the Start button) when a recently played title was
  long, at any window width. The columns now keep their size, and below
  1200 pixels wide the page is one column (Queue right after Now playing,
  Recently played last).

Lantern 1.11.0
==============

New
- Web player (Docker version's web page, Listen page): plays in your
  browser, on the speakers of the computer or phone you have the page open
  on. It has its own queue, separate from the Discord queue; both can play
  at the same time. Search YouTube (sc: for SoundCloud) and pick Play now,
  Play next or Add, or paste a link (YouTube, SoundCloud, Spotify, Apple
  Music, radio). Library songs and folders and radio stations have Play
  and Add buttons too. Play/pause, previous, next, seek (not live radio),
  shuffle, repeat (off, whole queue, this song), drag to reorder, remove,
  clear played, clear, and volume per device. The phone lock screen shows
  the song with play/pause and skip. Stations play live with a LIVE badge
  and reconnect if the stream drops. A song that can't play says why and
  moves on. The queue is saved on the server (lantern-webplayer.json).
- Audio goes to the browser as one Ogg Opus stream, decoded by the same
  code as the Discord player, so every source and radio format Lantern
  plays in Discord (HLS, AAC, MP3, Ogg, .pls/.m3u, YouTube with the yt-dlp
  backup) plays in the browser too. Even out volume applies.

Changed
- The web page is redesigned: Lantern's dark colors, a sidebar on a
  computer and a bottom bar on a phone, pages for Listen, Discord, Library,
  Radio, Settings and Activity, a mini player at the bottom of every page,
  cover art (YouTube thumbnails, station logos, album art from your files),
  and a whole-library search on the Library page. Every setting and tool
  from 1.10 is still there. No outside files are loaded; everything is in
  the program.

Lantern 1.10.1
==============

Fixed
- Radio stations that only stream HLS (an .m3u8 playlist of short pieces,
  like iHeart's "Nu Metal Radio") played nothing: Lantern joined, said
  Playing, and left 5 minutes later with no error. Lantern now follows the
  playlist itself: it picks the stream, fetches each new piece, and plays
  AAC, MP3 and MPEG-TS pieces as one live stream.
- Station links that are .pls / .m3u playlists, or redirect to one, are
  unwrapped to the stream inside.
- AAC streams with MPEG-2 or CRC frame headers decode.
- A track that couldn't be decoded, or that the player dropped before any
  audio played, now logs why and says so in the channel (also with Quiet
  on) instead of ending silently.

Lantern 1.10.0
==============

New
- Internet radio search (Radio Browser, radio-browser.info). On the web
  page, the Radio panel searches by station name, tag/genre and country
  and shows each station's logo, country, tags, codec and bitrate; Queue
  plays it (at once if nothing is playing). In Discord, `!radio <words>`
  (or `!station`) shows the top 4 to pick from like a YouTube search;
  `tag:jazz` and `country:Germany` narrow it. `/radio` does the same.
  `!radio on/off/soundcloud/youtube` still sets autoplay.
- Stations play live: no length limit, LIVE instead of a length on the web
  page and in the window, and a dropped stream reconnects (waits 2, 5, 10,

  as usual. Autoplay doesn't pick related songs after a radio station.
- Favorites: the Favorite button on Now playing saves a station like a song.
- Browse music on the web page: click through the music library folders
  like a file explorer. Breadcrumb path, folders first then songs, each
  song's title, artist, album and length from the library index, and a
  filter box for the folder you're in. Queue one song, a folder, or the
  folder you're in (and the folders inside it, up to 1000 songs, like the
  window's Add folder). Songs go to the server chosen in the server picker.
  Each folder loads only when you open it.
- Browsing never leaves the library folders: ".." is refused, and symlinks
  that lead outside are hidden and refused, also when a whole folder is
  queued.

Lantern 1.8.3
=============

Fixes
- A dropped voice connection is noticed and fixed. Before, if Discord's voice
  link died, Lantern kept "playing" (and autoplay kept picking songs) into
  nothing until someone stopped it. Now, when the voice link drops, Lantern
  pauses the song, rejoins the same voice channel, and carries on from where
  it paused. The queue, autoplay, and loop are kept. Autoplay itself is
  unchanged.
- Each new song also checks the voice link first, and a check every 15 seconds
  catches a link that died without saying so (Discord no longer lists Lantern
  in the channel).
- If rejoining fails it tries again after 5 s, 10 s, 30 s, 1 min, 2 min, then
  every 5 minutes, instead of spinning. Stop or leave ends the retries.
- Log lines: "Voice connection dropped (<why>); rejoining <channel>",
  "Rejoined <channel>; carrying on with <song>", and
  "Couldn't rejoin <channel> (try N: <why>); trying again in Ns".
- Stop now logs who did it: "Stopped by <user> via !stop" (or !leave, !dc,
  /stop, or the Stop button).

New
- Docker / Linux server build (lantern-server): no window or tray, settings
  and data from a /config folder, Discord token from the settings file or the
  DISCORD_TOKEN variable, music library from a read-only mount
  (LANTERN_LIBRARY). Dockerfile, docker-compose.yml, and an Unraid section in
  the README. The Windows app is unchanged.

Lantern 1.8.1
=============

Fixes
- Playback no longer stalls after a song ends. If a stream finishes or dies
  without the player noticing, Lantern now moves to the next song: when the
  position reaches the song's length and stops for 5 seconds, runs past it, or
  stops for 30 seconds mid-song after a real start. Pause never triggers this.
- Skip, Stop and leave now act on the very next check (within a quarter
  second), even if the stream never reports that it finished. Before, a stuck
  song kept the queue from moving and new songs were queued but never played.
- A player check that hangs is given up on after 3 seconds instead of
  blocking playback forever.
- The log notes "<song> stopped at m:ss of m:ss; moving on" when this happens.

=============

New
- First-run setup wizard. Opens by itself when there's no token: create the

Lantern 1.6.0
=============

New (in the order Jev ranked them)
- Playlist import and export. In the window: Import playlist queues a .m3u,
  .m3u8, .pls (Winamp, VLC) or .xspf (VLC) file. Files play from disk or a
  network share, links play like `play <link>`, and files that have moved or
  been deleted are skipped and counted. Export queue saves what's playing and
  the queue in the same four formats, so it opens in Winamp or VLC.
  In Discord: `import` with a playlist file attached, and `export [m3u|m3u8|pls|xspf]
  [saved playlist]` sends a file back. Discord imports play links, and paths
  only when that file is in the music library; Discord exports never include
  paths.
- Discord status: "Listening to <song>" now shows "(paused)", comes back after
  a reconnect, clears at once when the setting is turned off, and is only sent
  when it changes.
- Smaller exe: fat LTO, one codegen unit, optimised for size.
- Vote-skip: with 3 or more people listening, `skip` from someone who isn't the
  owner or a DJ is a vote; half of the listeners (rounded up) skips the song.
  The owner and DJs still skip at once.
- Recently played: a panel in the window lists the last 20 songs; click one to
  queue it again. `replay N` (or `/replay`) does the same from `history`.
- Volume leveling ("Even out volume between songs", on by default): uses
  ReplayGain tags in music files and YouTube's loudness figure so songs play
  at a similar level. Loud YouTube videos are turned down; nothing from
  YouTube is boosted.
- Sleep timer: `sleep 30m`, `sleep 1h30m`, `sleep end` (after this song),
  `sleep off`, `sleep` to see it. Stops and leaves the voice channel.
- Favorites: a ❤️ button on the Now playing message (anyone can use it), `fav`
  to add what's playing, `fav list`, `fav play` (your favorites shuffled into
  the queue), `fav remove 2`.

Lantern 1.5.0
=============

New
- Music library. Add folders in the window (Add library folder, Add server music
  share, or type any path or network share). Lantern reads
  title, artist, album, and length from mp3, flac, m4a, ogg, and wav tags and keeps
  the index in lantern-library.json. Rescan on open, on add, and with Rescan.
- `/local` (with autocomplete), `local <words>`, and `play local:<words>` play
  the best library match. Anyone who can use play can use them. Discord never
  sends a path, only search words or the short #key autocomplete picked. Only
  the window can add or remove folders.
- A library folder that can't be reached (share off, no saved login) keeps the
  tracks from its last good scan and shows why in the window and the log.
- `lyrics` / `/lyrics`: words for what's playing or for a named song, from
  lrclib.net (free, no key). The closest length wins; long lyrics are trimmed.
- Start Lantern when I sign in to Windows: a checkbox that adds or removes the
  per-user Run key entry.
- Install to a permanent folder: copies Lantern, settings, data, the library
  index, yt-dlp, and deno to %LOCALAPPDATA%\Lantern, adds a Start menu shortcut,
  moves Start with Windows there, and opens it. The old copy keeps working.
- yt-dlp gets a JavaScript runtime: Lantern downloads the official deno.exe next
  to itself in the background after yt-dlp is first used and passes it with
  --js-runtimes. Without it yt-dlp runs as before.

Fixed
- A YouTube stream that stops within 10 seconds of a song longer than 30 seconds
  is now a failure, not a finished song. Lantern logs why, drops its cached
  YouTube session, and retries that song once by the next route (Android VR,
  iOS, then yt-dlp). Before, such songs ended silently and the queue or
  autoplay moved on, so one broken session skipped song after song until a
  restart.
- Autoplay stops after 3 songs in a row fail, with a message in Discord, instead
  of cycling through recommendations that also fail.
- lantern-log.txt lines carry the date (the window still shows the time only).

Lantern 1.3.0
=============

New
- The queue panel can add music from this PC. **Add files** picks audio files.
  **Add folder** walks that folder and the folders inside it.
- Formats: mp3, m4a, ogg, opus, flac, wav, aac, webm. Other files are skipped.

Lantern 1.2.1
=============

A hardening pass on 1.2.0. No new features.

Fixed
- Saving `lantern-data.json` or settings no longer fails silently. The activity log records it, the window shows a one-time warning, and Discord commands that save (playlists, volume, DJ, autoplay) say when the file could not be written.
- Direct HTTP links to private or local addresses (`localhost`, `127.0.0.1`, `10.x`, `192.168.x`, link-local, CGNAT `100.64.x`, and IPv6 equivalents) are refused unless the requester is the **owner** (Owner ID in Settings). Redirects are checked hop by hop.

Lantern 1.2.0
=============

New
- YouTube backup: if YouTube's own clients (Vision, Android VR, iOS) stop working, Lantern
  falls back to yt-dlp. Songs, searches, and playlist/mix imports all have the fallback.
  Settings > "YouTube backup (yt-dlp)", on by default.
- yt-dlp.exe is taken from next to Lantern.exe, then from PATH. If neither has it, Lantern
  downloads the official release next to the exe the first time it is needed. The copy next to
  the exe is updated with yt-dlp -U at most once a day (or downloaded again if the update fails
  and it is over 7 days old). It runs with no console window and a time limit.
- The activity log says which route played each YouTube song ("via Android VR", "via yt-dlp"),
  and why earlier routes were skipped. Nothing extra is sent to Discord.

Fixed
- A YouTube audio link that YouTube refuses (403/410 or similar) no longer fails the song. Lantern
  tries the next client, then yt-dlp. This also covers a link refused while the song is starting,
  before any audio has played.

Notes
- Old settings files load unchanged; the new setting is on.
- New files next to the exe only if used: yt-dlp.exe and lantern-ytdlp-check.txt.
- No ffmpeg needed. yt-dlp is asked for m4a audio first, then WebM/Opus.
- Time allowed to load a song is now 120 seconds (was 45), so a slow client can't use up yt-dlp's turn.

Lantern 1.1.1
=============

A hardening pass on 1.1. No new features.

Fixed
- Now playing buttons answer Discord right away, so they no longer show "interaction failed"
  when stopping or redrawing the card is slow. A button on an old card (an earlier song, or from
  before a restart) removes its buttons instead of acting on the song that's playing now.
- A jump that arrived before a song's download had started could play audio from the wrong place
  (the start of the file filed under the new position). It now opens the right part.
- Seeking past the end of a stream (and a few odd MP4 files that do so while opening) now reads as
  the end of the file instead of asking the server for bytes that don't exist and failing.
- Idle auto-leave checks again at the moment it leaves, so a song queued just then isn't thrown away.
- Pressing Stop while autoplay was looking for a song no longer lets that song start anyway.
- Searching again before answering the first picker no longer cancels the second search.
- `dj` refuses a role ID that isn't a role in the server. A made-up ID could lock everyone out.
- Loading a saved playlist that is empty (a hand-edited file) says so instead of the command silently doing nothing.
- Settings and saved data: each save uses its own temporary file and is flushed to disk, so two saves
  can't overwrite each other and a power cut can't leave an empty file. A file with a Notepad
  byte-order mark loads. A file that can't be read is copied to .bak before anything overwrites it.
- The activity log file no longer loses lines when two parts of Lantern write at the same moment.
- Slash commands are sent to Discord once per run, not on every reconnect. A slash command Lantern no
  longer has gets a reply instead of "thinking" forever.

Tests
- The streaming source is tested against a small web server on localhost, with and without range
  support, including dropped connections, seeking past the end, and YouTube-style range pieces.
  The tests no longer need ffmpeg. Tests that need the internet are marked ignored.

Notes
- Setup: README has a Discord setup section with the intent, permissions, and an invite link template.

Lantern 1.1.0

- People who aren't the owner/DJ no longer get "owner only" for messages that aren't Lantern commands.

- Songs that fail to play are reported in the text channel.
- Skip names the song that was skipped.
- Search results now show the right length (it was off by a factor of 1000).
- A damaged settings file is kept as lantern-settings.json.bak instead of being lost.

Notes
- Old 1.0 settings files load unchanged.
- queue, np, help, history, and playlists can now be used by anyone. Everything that changes playback
  still needs the owner or the DJ role. If neither is set, everyone can do everything, as in 1.0.
- Discord: only the Message Content intent is needed. The bot needs Send Messages, Embed Links,
  Add Reactions, Read Message History, Connect, and Speak. Manage Messages is optional; it lets Lantern clear picker reactions.
- If the slash commands don't show up, press Ctrl+R in Discord.
